# PoetVerse 古诗词数据收集指南

本文管三件事：数据从哪来、哪些能用、入库前怎么洗干净。表结构与接口见《后端实现建议》。

## 一、数据源与收集顺序

按"授权明确程度"排序，先易后难。

### 1. 带授权标记的数据集（优先）

- [shiyun-corpus](https://github.com/Cohenjikan/shiyun-corpus)：每条记录自带授权标记（`PD` / `Apache-2.0` / `non-commercial` / `in-copyright`）。导入时优先 `PD`，再核对其他兼容授权；排除 `non-commercial` 和 `in-copyright`。
- [chinese-poetry/chinese-poetry](https://github.com/chinese-poetry/chinese-poetry)：最常用的开源古诗词数据集，JSON 按朝代 / 作者 / 作品组织，覆盖唐诗、宋诗、宋词。仓库标注为公版古籍整理，导入前仍需核对 `LICENSE` 与 `README`。
- [palemoky/chinese-poetry](https://github.com/palemoky/chinese-poetry)：上者的整理修正分支，字段更规整；同样先核对授权再用。

### 2. 大规模通用数据集（核对授权后用）

- [open-chinese/poetry-collection](https://github.com/open-chinese/poetry-collection)：规模大，字段含标题、作者、朝代、正文。导入前必须阅读仓库中的 `LICENSE` 和 `README`。
- [Chinese-Poetry-Dataset](https://github.com/iphinsau/Chinese-Poetry-Dataset)：唐诗、宋诗、宋词为主；同样需要核对许可证和数据来源。
- [palemoky/chinese-poetry-api](https://github.com/palemoky/chinese-poetry-api)：提供 REST API 与版本化数据包（见 [Releases](https://github.com/palemoky/chinese-poetry-api/releases)），适合原型期快速验证字段与接口形状，不建议作为长期唯一来源。

不能因为数据集可以下载，就默认其中所有内容都可以用于网站。

### 3. 维基文库（补充与人工校对）

[Wikisource 版权说明](https://wikisource.org/wiki/Help:Copyright)：站内多为公版或 CC BY-SA 作品，逐页确认：

- 公版作品：保存原文和页面来源即可。
- CC BY-SA 作品：保留作者、来源链接和许可证说明，并按 CC BY-SA 要求共享衍生内容。
- 页面中的现代翻译、校注、整理文本可能有独立版权，不能当作古代原文使用。

适合核对诗题、作者、句读、版本和出处，也适合补充数据集中缺少的篇目。

### 4. Chinese Text Project（只查证，不批量爬）

[Chinese Text Project](https://ctext.org/) 适合原文查找、版本对照和来源核验。其 [FAQ](https://ctext.org/faq) 明确限制自动化大规模下载：

- 只作为查证和引用来源，记录对应页面 URL。
- 不复制站上的现代译文、注释或赏析，除非已确认授权。

### 5. 公开古籍版本（最后补充）

从公开的古籍扫描本或已确认进入公版的历史版本中补充，再经人工校对。注意区分：古人原作多已进入公版，但现代标点、校勘、注释、赏析、白话翻译和重新整理的文本可能仍受保护。

## 二、授权筛选清单

每条诗词导入前按顺序检查，任一不通过即排除：

1. 作者、朝代、题名、正文是否完整。
2. 已记录原始来源与来源页面 URL。
3. 已记录许可证或版权状态。
4. 优先保留 `PD`（公版）条目。
5. CC BY / CC BY-SA / Apache-2.0 按许可证保存署名和声明。
6. 排除 `non-commercial`（除非网站明确非商业用途且已确认适用范围）。
7. 排除 `in-copyright` 或版权状态不明的条目。
8. 现代注释、翻译、赏析只用自有创作或已获授权内容。

## 三、标准记录结构

采集、入库、接口共用同一套逻辑字段，各层按命名规范映射：

| 逻辑字段 | 说明 | 采集 JSON | 数据库 |
| --- | --- | --- | --- |
| 标题 | 诗词标题 | `title` | `poems.title` |
| 作者 | 作者姓名（关联作者表） | `author` | `authors.name` |
| 朝代 | 如 唐、宋 | `dynasty` | `poems.dynasty` |
| 正文 | 原文，换行分隔诗句 | `content` | `poems.content` |
| 来源 | 数据来源名称 | `source` | `poems.source` |
| 来源链接 | 来源页面 URL | `sourceUrl` | `poems.source_url` |
| 许可证 | `PD`、`CC BY-SA` 等 | `license` | `poems.license` |
| 版本 | 集名 / 校勘信息，可空 | `edition` | `poems.edition` |
| 收集日期 | `YYYY-MM-DD` | `retrievedAt` | `poems.imported_at` |

示例：

```json
{
  "title": "静夜思",
  "author": "李白",
  "dynasty": "唐",
  "content": "床前明月光，\n疑是地上霜。\n举头望明月，\n低头思故乡。",
  "source": "Wikisource",
  "sourceUrl": "https://wikisource.org/wiki/Author:%E6%9D%8E%E7%99%BD",
  "license": "PD",
  "edition": "",
  "retrievedAt": "2026-10-17"
}
```

## 四、入库处理流程

固定流水线，不跳步：

```text
上传文件 → 解析 → 字段标准化 → 授权检查 → 去重 → 预览 → 人工确认 → 写入草稿 → 发布
```

细则：

1. 从授权明确的数据集导出原始记录。
2. 统一标题、作者、朝代、正文的字段名称。
3. 只清理多余空格和无意义换行，不擅自改动原文。
4. 用"作者 + 标题 + 规范化正文"去重（标题会重：同题诗、词牌名、异文版本）。
5. 逐条补齐来源、来源链接和许可证。
6. 随机抽取，与来源页面逐条比对。
7. 只将通过授权筛选和人工抽查的记录导入。
8. 上传接口不直接写已发布数据；先预览、人工确认，再进草稿、再发布。

## 五、网站内容建议

- 首批内容只用授权状态清楚的原文；赏析、译文、标签由项目自行编写。
- 每条诗词保留来源链接，方便后续校对和争议下架。
- 不复制第三方网站的整页排版、注释、图片和译文。
- 数据集授权发生变化时，凭导入日期和来源信息批量筛查。
- 在详情页或页脚提供来源说明和许可证说明。
