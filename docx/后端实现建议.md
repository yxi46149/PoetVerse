# PoetVerse 后端实现建议

> 2026-10-21 更新：公开页面已接入 NestJS + Prisma + MySQL 只读 API；后台写入与用户功能为后续阶段。

## 一、当前结构

- 前端：Vue 3 + Vite，页面通过 `src/services` 和 `src/types` 调用 API。
- 后端：`server/` 内独立的 ESM 项目，使用 NestJS 11 + Prisma 7。
- 数据库：MySQL 8，沿用 `db/schema.sql` 的五张表和已导入诗词。
- API 只读：后端启动不执行建表、迁移、重置或导入，Prisma 模型映射现有数据库。

本地启动步骤见 [项目说明](../README.md)。开发时前端使用 `localhost:3300`，API 使用 `localhost:8080/api`，Vite 将 `/api` 请求代理给后端。前端 `VITE_API_BASE_URL` 默认 `/api`。

`server/.env` 配置示例：

```dotenv
DATABASE_URL=mysql://USER:PASSWORD@HOST:3306/poetverse
HOST=127.0.0.1
PORT=8080
```

连接信息由实际数据库提供，密码中有特殊字符时需 URL 编码。`server/.env` 不应提交到版本库。

## 二、公开接口

以下接口均使用 `GET`，诗词列表、详情和统计只包含 `status='published'` 的记录：

| 路径 | 用途与返回 |
| --- | --- |
| `/api/poems` | 分页查询诗词，返回 `{ items, page, pageSize, total }` |
| `/api/poems/featured` | 首页场景选诗，返回最多 5 首诗词，每项增加 `scene` 场景名称 |
| `/api/poems/random` | 随机选诗，返回 `{ id }`；可用 `exclude` 排除一个 UUID |
| `/api/poems/:id` | 诗词详情，包含作者简介 `authorBio` 和 `navigation.previousId/nextId` |
| `/api/catalog` | 筛选词表，包含 `dynasties`、`forms`、`tags` 字符串数组 |
| `/api/dynasties` | 有已发布作品的朝代字符串数组 |
| `/api/forms` | 有已发布作品的体裁字符串数组 |
| `/api/tags` | 有已发布作品的标签字符串数组 |
| `/api/authors` | 作者分页列表，支持 `q`、`dynasty`、`page`、`pageSize` |
| `/api/overview` | 公开数据统计和最近导入日期 `latestImportedAt` |
| `/api/health` | API 与数据库连接状态 |

首页精选按山水、月夜、送别、相思、咏春排序，分别从现有诗库匹配王维《鹿柴》、张继《枫桥夜泊》、王昌龄《芙蓉楼送辛渐》（其一）、王维《相思》、孟浩然《春晓》。正文、标题和来源保留数据库版本；候选作品不存在或未发布时省略该项。

`GET /api/poems` 查询参数：

| 参数 | 含义 |
| --- | --- |
| `q` | 标题、作者、正文关键字 |
| `dynasty` | 朝代 |
| `form` | 体裁 |
| `tag` | 标签 |
| `author` | 作者姓名 |
| `page` | 页码，从 1 开始 |
| `pageSize` | 每页条数 |
| `sort` | `default` 或 `latest` |

分页示例：

```json
{ "items": [], "page": 1, "pageSize": 20, "total": 0 }
```

页面展示服务返回的加载、空数据和错误状态。数据库没有的译文、赏析、收藏数等内容不应生成成真实数据。

## 三、数据约束

实际字段、索引和外键以 [schema.sql](../db/schema.sql) 为准，Prisma 映射位于 `server/prisma/schema.prisma`。

- `authors`：按 `(name, dynasty)` 唯一，简介允许为空。
- `poems`：保留正文、作者冗余姓名、朝代、体裁、来源、许可证、状态和导入日期；`author_id` 允许为空。
- `tags` / `poem_tags`：标签及关联分别保存 `auto` 或 `manual` 来源。
- `import_batches`：保留脚本导入统计，目前没有逐条导入记录或与诗词的批次外键。
- `dedup_hash`：对 `作者姓名 + "\n" + 标题 + "\n" + 规范化正文` 计算 SHA-256。规范化规则与 `scripts/import-poems/clean.py` 保持一致，移除指定空白和标点。

当前表中没有用户、收藏、阅读记录、译文和赏析。新增这些能力时再设计表结构与迁移，不能假定已有对应字段。

当前关键字查询覆盖标题、作者和正文；现有表未建中文全文索引。后续根据真实查询耗时评估组合索引、MySQL ngram 全文检索或独立搜索服务。

## 四、后续阶段

### 后台管理与导入

- 增加账号与角色模型，采用 JWT + HttpOnly Cookie；不在 `localStorage` 保存长期令牌。
- 后台接口统一 `/api/admin` 前缀，按管理员、编辑角色限制内容写入。
- 实现诗词新增、编辑、删除和发布；状态为 `draft`、`published`、`archived`。
- 所有写入进行 DTO 校验；修改作者、标题或正文时同步更新规范化正文和去重值。
- JSON/CSV 导入先解析、校验授权与去重，再预览、人工确认、写入草稿、发布；保留来源与处理结果。

现有后台页面不代表已具备真实登录和 CRUD API。当前后端没有开放管理写入接口。

### 用户功能

增加用户、收藏、阅读记录等表后，再实现登录、个人收藏和阅读进度。普通用户只能管理自己的记录；收藏通过用户和诗词的唯一键防重。

## 五、部署与来源

生产环境由静态服务器托管前端，并将 `/api` 转发到 NestJS。API 连接独立 MySQL，部署时配置环境变量、数据库备份、错误日志和 HTTPS。

数据来源、授权筛选和现代译注的使用边界见 [古诗词数据收集指南](古诗词数据收集指南.md)。每条作品的来源 URL、许可证与导入日期应保留，方便后续校对和下架处理。
